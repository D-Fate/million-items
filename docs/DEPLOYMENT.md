# Деплой в Amvera

Express обслуживает собранный Angular и API по одному адресу. Сборка и запуск описаны в `Dockerfile`, настройки портов — в `amvera.yaml`.

## Настройки приложения

| Параметр | Значение |
| --- | --- |
| Тип | Приложение |
| Регион | Москва / российский регион |
| Окружение | Docker |
| Dockerfile | `Dockerfile` в корне репозитория |
| Переменные | `PORT=3000`, `NODE_ENV=production` |
| Порт контейнера | 3000 |
| Порт сервиса доступа | 80 |
| Реплики | 1 |
| Health check | `/api/health` |

Для небольшой демонстрации можно начать с тарифа «Начальный» с 500 МБ памяти. Если сборка завершается из-за нехватки памяти, увеличьте тариф и повторите её. Актуальная стоимость указана в [тарифах Amvera](https://docs.amvera.ru/general/price.html).

## Публикация

1. Создайте приложение в [кабинете Amvera](https://cloud.amvera.ru/) с параметрами из таблицы.
2. Во вкладке «Переменные» задайте `PORT=3000` и `NODE_ENV=production` без кавычек. После изменения переменных работающий контейнер нужно перезапустить.
3. Скопируйте HTTPS-адрес из вкладки «Репозиторий».
4. Из локального Git-репозитория отправьте код следующими командами, заменив `<repository-url>` скопированным адресом:

```sh
git remote add amvera <repository-url>
git push amvera HEAD:master
```

При запросе авторизации используйте учётную запись Amvera. Отправка в удалённую ветку `master` запускает сборку; имя локальной ветки может быть `main`.

5. Дождитесь завершения сборки. В журнале приложения появится `Listening on http://localhost:3000`.
6. Во вкладке «Домены» добавьте «Бесплатный домен Амвера» с подключением HTTPS и дождитесь выдачи сертификата.
7. Откройте внешний адрес приложения и `/api/health`. Ожидаемый статус — `ok`.

В проекте один порт: отдельные маршруты к портам в настройках домена не нужны. К публичному адресу не добавляется `:3000`. Сборка и команда запуска берутся из Dockerfile.

Для обновления сохраните изменения в Git и повторите `git push amvera HEAD:master`. Деплой сбрасывает состояние в памяти.

## Проверка и диагностика

После публикации проверьте загрузку страниц, выбор, сортировку и добавление ID. При свободной очереди добавление занимает до 10 секунд. Обновление страницы сохраняет выбор и сбрасывает фильтры.

- **502/503:** проверьте `PORT=3000`, порт контейнера и журнал запуска.
- **OOMKilled / код 137:** увеличьте доступную память и повторите сборку или запуск.
- **504 при добавлении:** проверьте таймаут входящего трафика. При заполненной очереди ожидание может достигать 60 секунд; таймаут прокси должен учитывать это с запасом.
- **Разные данные между запросами:** убедитесь, что запущена одна реплика.

Лимиты входящего трафика Amvera действуют отдельно от ограничений приложения. Контейнерную сборку и публичную доступность нужно проверить на самой площадке.

## Docker локально

При работающем Docker Engine:

```sh
docker build -t million-items .
docker run --rm -p 3000:3000 -e PORT=3000 --name million-items million-items
```

Приложение доступно на http://localhost:3000. Контейнер запускается от пользователя `node`.

Документация Amvera: [Docker](https://docs.amvera.ru/applications/configuration/docker.html), [Git](https://docs.amvera.ru/applications/git/main-origin.html), [сеть и домены](https://docs.amvera.ru/applications/configuration/network.html).
