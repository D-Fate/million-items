# Запуск в production

Express обслуживает API и собранный Angular по одному адресу. Для запуска нужен Node.js 24.15+ в пределах ветки 24 или Docker.

## Node.js

Из корня проекта:

```sh
npm ci --include=dev
npm run build
```

Перед запуском задайте переменные окружения:

| Переменная | Значение |
| --- | --- |
| `NODE_ENV` | `production` |
| `PORT` | `3000` или другой свободный порт |

```sh
npm start
```

Сервер слушает `0.0.0.0`. При порте 3000 приложение доступно на http://localhost:3000, проверка работоспособности — на http://localhost:3000/api/health. В ответе ожидается `"status":"ok"`.

## Docker

```sh
docker build -t million-items .
docker run --rm -p 3000:3000 --name million-items million-items
```

Dockerfile фиксирует версию Node.js, устанавливает зависимости и собирает клиент и сервер. Финальный контейнер запускает Express от пользователя `node`, с `NODE_ENV=production` и `PORT=3000`.

Для доступа с хост-машины через другой порт измените левую часть привязки, например `-p 8080:3000`.

## Требования к окружению

- Запускайте один процесс приложения. Состояние хранится в памяти; несколько реплик получат независимые списки.
- Для публичного доступа настройте HTTPS на обратном прокси, направляющем запросы на порт приложения.
- Добавление ID обычно занимает до 10 секунд. При заполненной очереди ожидание может достигать 60 секунд, поэтому таймаут прокси должен быть больше этого значения, например 75 секунд.
- Перезапуск процесса и обновление контейнера сбрасывают добавленные ID, выбор и порядок.

## Проверка запуска

1. Убедитесь, что `/api/health` возвращает статус `ok`.
2. Откройте главную страницу и проверьте загрузку списка, поиск, выбор и сортировку.
3. Добавьте новый ID и дождитесь обработки очереди.
4. Обновите страницу: выбор должен сохраниться, а фильтры — очиститься.

При ошибках 502/503 проверьте журнал сервера и совпадение порта приложения с настройками прокси. При завершении с `OOMKilled` или кодом 137 проверьте доступную память. Различающиеся данные между запросами могут указывать на запуск нескольких реплик.
