# API

Все пути начинаются с `/api`. Тело запросов и ответов - JSON. Максимальный размер тела - 4 KiB.
Ответ на бизнес-запрос отправляется после выполнения операции в очереди, а не после постановки в нее.

## Список

`GET /api/items?side=available&q=12`

| Параметр | Значение |
| --- | --- |
| `side` | `available` или `selected`, обязателен |
| `q` | подстрока ID, по умолчанию пустая, максимум 128 единиц UTF-16 |
| `cursor` | значение `nextCursor` предыдущего ответа |

```json
{
  "items": ["12", "112", "120"],
  "nextCursor": null,
  "revision": "instance-uuid:4",
  "totals": { "all": 1000000, "selected": 3 }
}
```

Пример показывает формат ответа; количество результатов зависит от фильтра и состояния. `nextCursor: null` означает конец списка. Максимум - 20 элементов; клиент не может увеличить этот лимит. Счетчики показывают количество всех и выбранных элементов, а не число совпадений фильтра.

Курсор содержит позицию, сторону, фильтр и версию состояния. Он предназначен для продолжения конкретного запроса. Это не токен доступа; подпись ему не требуется, так как все данные общедоступны. При изменении состояния сервер отвечает `409 STALE_REVISION`, клиент перечитывает первую страницу.

## Новый ID

`POST /api/items`

```json
{ "id": "project-2026" }
```

Успех: 201. Операция выполняется в ближайшем пакете добавлений раз в 10 секунд, при заполненной очереди - позже. Дубликат уже существующего ID: `409 ID_EXISTS`.

## Выбор

`PUT /api/selection`

```json
{ "id": "12", "selected": true }
```

`false` возвращает элемент в левый список. Повтор того же желаемого состояния ничего не меняет. Успех: 200. Неизвестный ID: 404.

## Изменение порядка

`POST /api/selection/move`

```json
{
  "id": "21",
  "targetId": "1",
  "placement": "before",
  "revision": "instance-uuid:4"
}
```

`placement` - `before` или `after`. Оба ID должны быть выбраны. Версия берется из ответа правого списка. Сервер перемещает один элемент относительно другого в полном порядке, поэтому фильтрация не влияет на корректность операции. Успех: 200. Устаревшая версия: 409. Исчезнувший выбранный ID: 404.

Успешные изменения возвращают `{ "revision": "...", "totals": { "all": 1000000, "selected": 3 } }`.

## Ошибки

```json
{
  "error": {
    "code": "ID_EXISTS",
    "message": "Элемент с таким ID уже существует."
  }
}
```

| HTTP | Коды | Действие клиента |
| --- | --- | --- |
| 400 | `INVALID_INPUT`, `INVALID_JSON` | исправить входные данные |
| 404 | `NOT_FOUND`, `NOT_SELECTED` | обновить список |
| 409 | `ID_EXISTS` | выбрать другой ID |
| 409 | `STALE_REVISION` | перечитать первую страницу, повторить перенос вручную |
| 413 | `PAYLOAD_TOO_LARGE` | сократить тело запроса |
| 429 | `QUEUE_FULL`, `TOO_MANY_REQUESTS` | повторить позже с учетом `Retry-After` |
| 503 | `QUEUE_TIMEOUT`, `SHUTTING_DOWN` | проверить состояние и повторить позже |
| 500 | `INTERNAL_ERROR` | проверить журналы сервера |

Ожидающие одинаковые запросы могут разделять один результат. Отмена HTTP-запроса клиентом не отменяет уже принятую запись. Поэтому после сетевой ошибки интерфейс предлагает проверить состояние перед повтором; автоматического повтора записей нет.

## Проверка работоспособности

`GET /api/health` отвечает немедленно:

```json
{ "status": "ok", "queues": { "regular": 0, "additions": 0, "processing": false } }
```

`regular` и `additions` показывают ожидающие операции, без уже извлеченного пакета. Этот маршрут используется хостингом для health check.
